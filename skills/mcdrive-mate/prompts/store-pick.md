# Prompt 片段：选店决策逻辑（比时间，不比价格）

> 用户给出位置/目的地/路线后，按本逻辑输出选店决策卡。

## 输入收集（缺一项问一项，一次问完）

1. **当前位置或途经点**（必要）——"你在哪 / 路过哪个路口？"
2. **预计到达时间或可接受等待**（必要）——"大概几点到？"
3. **就餐方式偏好**（可选，默认三案并陈）——到店取 / 得来速 / 麦乐送

## 决策步骤

```
1. query-nearby-stores(位置)        → 附近门店候选集
2. delivery-query-addresses         → 用户有无已存地址
3. 若用户想去的是"目的地"而非"当前位置"：
   用目的地坐标再查一次，候选集合并
4. 若存在已存地址：
   delivery-query-stores(地址)      → 外送可行门店
5. 生成决策卡（最多 3 行）
```

## 总耗时估算口径（回复中注明"预计"）

| 方式 | 总耗时 = |
|---|---|
| 到店取（预约单） | 剩余路程时间 + 取餐停留（默认 3 分钟，预约成功后取餐停留≈0） |
| 得来速 | 剩余路程时间 + 车道排队（保守估 4–6 分钟） |
| 麦乐送 | 出餐 + 配送全程（以 `calculate-price` 返回的配送信息为准） |

- 无法精确获知排队/路况时，**明确说这是估计值**，禁止编造精确数字（如"排队 4 分 37 秒"）。
- 排序规则：预计总耗时升序；耗时差 ≤ 2 分钟视为并列，此时用价格/顺路程度作次级排序。

## 决策卡输出

格式见 SKILL.md §5。每行必须含：门店名、方式、预计总耗时、一句说明。推荐行置顶并标 ✅。

## 特殊规则

- **深夜**：只列仍在营业的门店，并注明各自关门时间。
- **外送与到店耗时接近**（差 ≤ 5 分钟）时，提示"外送贵 xx 元但省去停留"，让用户选。
- **用户赶时间（"我只有 10 分钟"）**：只保留预计总耗时 ≤ 10 分钟的方案，不足时如实说"来不及，建议改约 XX 点的预约单"。
- 禁止基于猜测贬低任何门店（"这家出餐慢"必须有依据，没有就不说）。
